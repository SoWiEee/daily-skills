# Slide Grammar：27 種頁型

每一種 Grammar 都有教學用途。選擇流程必須先經過 Layout Decision Engine。

## 結構類

### G01 Cover
用途：第一頁與 Deck Identity。  
Rhythm：`anchor`。  
Composition：Title、Subtitle、授課資訊，再加一個強但克制的視覺線索。

### G02 Section Divider
用途：Major Topic Shift。  
Rhythm：`anchor`。  
Composition：Section Number、短 Title、可選一行 Framing Statement。

### G03 Learning Objectives
用途：告訴學生這一段課後要能解釋、判斷或實作什麼。  
Rhythm：`anchor`。  
Composition：3 到 5 個 Action-oriented Outcome，可依 Concept / Practice 分組。

### G04 Recap Map
用途：重新組織已教過概念的關係。  
Rhythm：`anchor`。  
Composition：Concept Map、Causal Chain、Matrix 或 Structured Synthesis，不重複貼前面 Bullet。

### G05 Key Takeaway
用途：Section 或整份課程的具體收束。  
Rhythm：`breathing`。  
Composition：一個主要命題，加 1 到 3 行必要支持資訊。

### G06 Breath / Statement
用途：Pause、Thesis、Transition。  
Rhythm：`breathing`。  
Composition：一個 Statement，可加一行限定條件。

## 解釋類

### G07 Concept + Visual
用途：一個抽象 Concept 搭配 Diagram 與短說明。  
Rhythm：`dense` 或 `anchor`。  
Composition：常用 35/65 或 40/60，Visual 通常拿較大區域。

### G08 Definition
用途：建立精確術語。  
Rhythm：`breathing` 或 `dense`。  
Composition：短 Definition + Visual Anchor，必要時加 Boundary / Non-example。

### G09 Three-Part Explanation
用途：內容真的有三個 Dimension、Reason 或 Component。  
Rhythm：`dense`。  
Composition：偏好一主兩輔的非對稱配置。不要做三張完全一樣的 Card。

### G10 Layer Stack
用途：Abstraction、Trust Boundary、Protocol Stack、Defense Layer、Maturity Level。  
Rhythm：`dense`。  
Composition：水平堆疊 Layer，Label 一致。

## 關係類

### G11 Two-Column Parallel
用途：兩個並列 Concept，沒有強烈好壞判斷。  
Rhythm：`dense`。  
Composition：50/50 或 45/55，左右 Hierarchy 對齊。

### G12 Matched Comparison
用途：A 與 B 用相同維度比較。  
Rhythm：`dense`。  
Composition：Mirrored Columns 或 Matrix，Dimension 順序一致。

### G13 Before / After
用途：Impact、Migration、Improvement、State Change。  
Rhythm：`breathing` 或 `dense`。  
Composition：Old State → Transition → New State。

### G14 Transformation
用途：Representation、Model、Resource 或 Encoding 改變本身就是教學重點。  
Rhythm：`dense`。  
Composition：Source → Transformation → Resulting Model。

### G15 Trade-off
用途：Competing Objectives。  
Rhythm：`dense`。  
Composition：Spectrum、Pareto-style Chart 或 Matrix。避免把連續問題硬切成二元選擇。

## 流程與系統類

### G16 Process Flow
用途：Ordered、Non-branching Process。  
Rhythm：`dense`。  
Composition：3 到 7 個 Step，箭頭與 Stage Label 清楚。

### G17 Decision Flow
用途：Conditional Path 或 Policy Logic。  
Rhythm：`dense`。  
Composition：Decision 與 Branch Label 清楚。

### G18 Timeline
用途：Chronology 或 Lifecycle。  
Rhythm：`dense`。  
Composition：Time Axis + Milestone Emphasis。

### G19 Architecture Diagram
用途：Component、Interface、Trust Boundary、Deployment / System Topology。  
Rhythm：`anchor` 或 `dense`。  
Composition：Full-canvas Diagram + 精簡 Legend / Callout。

### G20 State Transition
用途：行為由 State 與 Transition 決定。  
Rhythm：`dense`。  
Composition：Named State + Labeled Transition。

## 證據與資料類

### G21 Table / Matrix
用途：精確 Row-column Lookup。  
Rhythm：`dense`。  
Composition：Highlight 1 到 3 個關鍵 Cell / Row，不做過度裝飾。

### G22 Chart
用途：Trend、Distribution、Correlation、Proportion、Quantitative Comparison。  
Rhythm：`dense`。  
Composition：Chart 為主體，Title 直接寫 Interpretation，Source 可見。

### G23 Big Number
用途：一個值得單獨記住的 Metric。  
Rhythm：`breathing`。  
Composition：Number 是 Hero，加一行解釋與 Source。

### G24 Evidence / Source
用途：Screenshot、Paper Figure、Official UI、Quote 或 Documentary Evidence。  
Rhythm：`dense` 或 `breathing`。  
Composition：Evidence 佔主要空間，加 Annotation 與 Source Link。

## 技術與練習類

### G25 Code Walkthrough
用途：Code Semantics、Execution、Configuration、Terminal Output。  
Rhythm：`dense`。  
Composition：Code + 1 到 3 個 Callout，或 Code + Execution Trace。

### G26 Worked Example
用途：逐步應用 Concept。  
Rhythm：`dense`。  
Composition：Initial State / Problem → Reasoning State → Result，可跨多頁。

## 互動類

### G27 Check Your Understanding
用途：Prediction、Conceptual Choice、Debugging Question、Mini Exercise。  
Rhythm：`breathing`。  
Composition：一個清楚問題，可搭 Choices / Diagram。答案放後頁或使用 Reveal。

## 共通規則

- 每頁一個 Primary Claim
- Grammar 由 Information Relation 選擇
- Card Grid 需要真的有 Category Semantics
- Diagram 先呈現關係，文字補推理與限制
- Grammar 過載就拆頁
- G21 Table 不拿來教 Causal Mechanism
- G25 Code 只放講者會解釋的 Code

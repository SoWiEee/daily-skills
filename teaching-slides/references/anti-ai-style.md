# 避免 AI 味：繁體中文文稿與視覺規則

這份規則依使用者提供的「AI 味避用詞庫」整理，並針對技術教學簡報調整。目標是讓文字具體、自然、有判斷，也讓版面看起來像經過教學設計，而非模型套模板。

## 1. 中文語境

除術語、API、Framework、Library、Command、Code、論文題名與品牌名外，使用台灣常見的繁體中文說法。

優先寫具體動作：

- 「說明 App 怎麼取得權限」比「權限機制的闡述」直接
- 「把 Job 綁到 GPU」比「工作負載配置的落地」直接
- 「這三個欄位會影響排程」比「三個關鍵面向共同賦能排程決策」直接

技術術語本來就叫 integration、scalability、consistency 時可以保留精確術語，不為了避詞而改壞意思。

## 2. 預設避用詞

除非是來源原文、固定術語或真的沒有更精確寫法，文稿與講稿不要使用這些泛用詞：

- 賦能、賦予
- 深入探討、深入研究
- 凸顯、突顯
- 闡述
- 涵蓋
- 落地
- 接軌
- 格局、版圖、藍圖
- 解方
- 賦能機制、增長引擎

常見空泛形容詞也要限量：

- 強大、全面、高效、便捷、卓越、先進、豐富、多元
- 關鍵、重要、核心、本質，如果同一段重複就改寫成具體原因
- 不可或缺、不容忽視、不可磨滅

## 3. 連接詞與教科書腔

少用過度書面連接詞。能直接講就直接講。

常見替代：

- 「此外」可改成「另外」或直接換句
- 「然而」可改成「但」或「不過」
- 「故而、因而」改成「所以」
- 「由此可見」直接寫結論
- 「相較於」改成「跟 X 比」
- 「進而」改成「接著」
- 「倘若、若是」改成「如果」

下列開場通常直接刪掉：

- 值得注意的是
- 重要的是要記住
- 需要強調的是
- 顯而易見的是
- 不可否認的是
- 綜上所述

## 4. 修辭限制

### 對仗式反轉金句

預設不用工整的 X／Y 反轉句型來製造金句感。直接寫真正的判斷與原因。只有來源引用或使用者明確要求文案語氣時才例外。

### 三段排比

教學上真的有三個維度，可以做三項結構。不要把三個近義形容詞或空泛動詞排成口號。修辭性三段排比每 600 個中文字最多一次。

### 反問設問

不要用「你是否曾經……」「答案很簡單」這類課本式開場。Check-your-understanding 可以問問題，但問題必須測到明確 Learning Goal。

### 虛假範圍

不要用跨度很大的「從 A 到 B」營造宏大感。只有 A 到 B 真的是連續範圍、流程或時間軸時才使用。

## 5. 模糊歸因禁止

不要寫沒有來源的：

- 研究顯示
- 許多人認為
- 專家指出
- 業界普遍認為

外部主張要能回答「哪個研究、哪個組織、哪個 Dataset、哪份官方文件」。如果找不到，改成講者自己的限定判斷，並把條件寫清楚。

## 6. 標點與格式

- 長破折號完全禁用。改成句號、逗號、冒號或括號。
- 正式教學簡報不用 Emoji 裝飾段落或 Bullet。
- 不要每段都粗體。投影片用字重與 Accent 只標真正的 Focus。
- Speaker Notes 優先用段落，不把所有內容拆成清單。
- Markdown 的 `##`、`**` 不得殘留到最終可視畫面。

## 7. 具體錨點規則

抽象概念一定要找可觀察的東西落腳。技術課程的「人味」通常來自具體條件，而非感性敘事。

可用錨點：

- `25% / 50% / 75% / 100%` 這種實際 share
- `kubectl get pods` 這種 Command
- 一段真實 Code
- 一張 GPU 上的 Job A / Job B
- 明確 Version、Date、Dataset、Paper、CVE 或 Benchmark
- 一個會失敗的 Input

每個主要 Section 至少安排一個具體 Example、Trace 或 Evidence。

## 8. 結尾規則

不要在每一章都放口號式「總結」或「未來展望」。Section 結束可以用：

- 一張 Recap Map
- 一個 Check
- 一個具體 Takeaway
- 下一段需要回答的問題

整份課程的最後一頁可以回到最初 Learning Goals 或留下後續實作題，不要硬做昇華文案。

## 9. 視覺 AI 味

### 禁止預設套路

- 三張或四張完全相同的圓角卡片
- 每個 Bullet 配一個 Emoji 或泛用 Icon
- Glassmorphism、霓虹漸層 Blob、沒有語意的 Glow
- 每張頁面都用同一個 Card Grid
- 大量 Pill / Tag 當主要資訊結構
- 裝飾箭頭當成流程圖
- 用 Dashboard KPI 卡片解釋非 Dashboard 內容
- 為了填空間加假的 Chart、假 Code、假 Terminal

### 允許 Card 的條件

Card 只在資料本來就是相互獨立的 Category 時使用。即使使用 Card，也要讓重要性、內容深度或比例有差異，避免每張完全同構。

### Diagram 要有語意

每個 Node 要有角色，每條 Edge 要有方向或關係。顏色用來標 Teaching Focus 或固定 Category，不當純裝飾。

### 跨頁變化

連續 4 張使用相同 Composition 視為警訊。除非連續 Step-by-step Trace 需要位置穩定，否則要改變焦點與空間安排。

## 10. 最終自檢

文稿完成後至少確認：

- [ ] 沒有長破折號
- [ ] 沒有連續出現工整反轉金句
- [ ] 沒有無來源的「研究顯示」或「專家指出」
- [ ] 每個主要 Section 有具體 Example、數字、State、Code 或 Evidence
- [ ] Bullet 都是真正的 List
- [ ] 沒有用空泛形容詞代替原因
- [ ] 沒有每頁都長成相同 Card Grid
- [ ] Diagram 的 Edge 與 Node 都能說出語意
- [ ] 結尾沒有口號式昇華
